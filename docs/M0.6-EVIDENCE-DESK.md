# M0.6 — Evidence Desk

## Objective

Fill the evidence gap between Channel3 catalog discovery and a policy decision without pretending catalog metadata proves checkout/fulfilment facts. A user can record a specific field observed on the selected merchant page, cite an HTTPS URL on the same merchant domain, and explicitly mark that submitted claim human-reviewed.

## Data model

`pactpay_offer_evidence` stores immutable claims:

- exact Channel3 snapshot reference;
- normalized field and primitive value;
- canonical merchant source URL/domain;
- server-received timestamp and PactPay-local validity deadline;
- optional note and SHA-256 content hash.

`pactpay_offer_evidence_reviews` is append-only and stores review decisions separately. The latest review event controls eligibility. Unreviewed and rejected observations do not enter the policy evaluator.

## Policy semantics

Only `HUMAN_REVIEWED` claims are added as merchant-source evidence. Freshness is checked by the existing deterministic evaluator. For each field, the current value is selected from the latest fresh reviewed claim; if multiple fresh reviewed claims for the same field disagree, the existing conflict logic yields `unknown` and blocks policy completion. Unknown shipping, delivery, total, returns, or product attributes remain unknown unless an eligible claim supports the field.

## Security and limitations

The intake does not server-fetch user-supplied URLs, avoiding an arbitrary-URL fetch/SSRF surface. It validates HTTPS, rejects credentials and nonstandard ports/IP addresses, and requires the canonical hostname to equal the stored merchant domain or be its subdomain. Query strings and fragments are stripped before persistence to avoid storing session/tracking tokens. This is source-domain binding, **not proof of page authenticity**.

Reviewer identity is currently the literal local-demo label `local_demo_user`, with no auth. This is intentionally not production-ready. Future work must add real authentication/authorization, evidence screenshot or browser-capture provenance, authenticated/controlled reviewer identities, rate limits, and a stronger mechanism to establish the exact content seen by the reviewer.

## Payment invariant

The Evidence Desk makes no PayPal calls. `paymentAction` is always `NONE`; no capture endpoint is introduced. A future settlement controller must independently enforce authorization state, hard constraints, evidence freshness/provenance, currency/amount binding, and security state at execution time.
