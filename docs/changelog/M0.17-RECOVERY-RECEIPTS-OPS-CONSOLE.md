# M0.17 · Honest recovery, decision receipt, operations console

**Fixed (reviewer P0): the agent re-picked an offer that had just failed**
- Cause: skipped offers were remembered by snapshot id, but every search creates a new snapshot of the same offer, so the skip never matched.
- Offers now have a stable identity (product + merchant). A change made with Demo control is stored server-side for the session (`pactpay_seller_world`) and stays in effect until reset. The agent excludes those offers and must pick a genuinely different one, or stop. `/api/paypal/offer-demo/orders` also refuses (409) to open a hold on such an offer.
- `GET/DELETE /api/seller-world`; "Reset the simulation and search again" on the shortlist.
- Direct tests (`seller-world.test.ts`): for out-of-stock, price increase, hidden instruction and currency change, policy blocks, the gate returns BLOCK and never reaches CAPTURE_ELIGIBLE; offer identity is stable across new snapshots.

**Result page accuracy (P0)**
- "Sandbox payment captured" / "Authorization voided" instead of "released to the seller". Every result states that no retailer order was placed.
- "PayPal confirms" line read live from PayPal: authorization status and captured amount.
- "Attempts in this run" table: each hold, its authorization, what was captured, why it failed, and whether the next attempt used a different offer.

**Decision receipt (P1)**: rule you approved, observed value, evidence source, collected/valid-until times, and PASS / FAIL / UNKNOWN per rule, with the evidence freshness and security checks and the final decision.

**Repeatable security demonstration (P1)**: "Source, test change, decision" strip separates the live catalog data, what Demo control injected, and PactPay's decision.

**AG Grid operations console (P1)**: attempt number, offer, outcome, captured amount, failed rules, evidence state, injected change, autonomy; quick filters (captured, voided with nothing captured, stale or unchecked evidence, needs review, run by the agent); expandable hash-chained event lineage per row (`/api/control-center/lineage/[id]`, session-scoped).
