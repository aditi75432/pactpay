# M0.14.1 — Agent handoff and live PayPal state

## Agent handoff contract

The agent must pass only its refreshed candidate shortlist to Discovery. The selected snapshot ID must be a member of the shortlist and have a stored evaluation. The browser session cache is retained during the short handoff window so reloads don't trigger a new unfiltered search. If it is missing, Discovery explicitly asks the user whether to run a new catalog search rather than doing so silently.

## PayPal status refresh

`GET /api/paypal/transactions/[transactionId]/refresh-state` is read-only. It fetches the existing PayPal Sandbox order and authorization, plus the capture resource if one is present. It reports both local and remote statuses and compares transaction binding, amount, currency, authorization/capture status and audit integrity. It never calls capture or void.

If a completed capture is visible remotely while local status remains CAPTURE_REVIEW, the UI may offer the existing `POST .../reconcile-capture` operation after preliminary verification. That endpoint independently verifies its preconditions and all remote relationships before updating the local state.

## What a Sandbox “payment” means

PayPal Sandbox uses virtual test funds. A completed Sandbox capture demonstrates a working PayPal API state transition, not a real-money transfer or an order at the Channel3-listed retailer. The selected product, merchant and catalog price are live Channel3 data. Shipping, tax and deliberate drift remain clearly labelled PactPay test-fixture data until a supported real merchant checkout adapter is integrated.
