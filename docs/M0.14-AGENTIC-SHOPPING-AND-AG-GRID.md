# M0.14 — Tool-using Shopping Agent and AG Grid Control Center

## What this milestone does

PactPay now has two clearer product surfaces:

1. **Shopping Agent (`/agent`)** — starting from the approved Purchase Pact, one user action runs a bounded tool chain:
   - Calls the live Channel3 search API and persists returned offer snapshots.
   - Evaluates each saved snapshot against the approved Pact using the server-side deterministic policy engine.
   - Selects up to three leading candidates that did not fail a hard rule, refreshes each through Channel3's product-detail route, and re-evaluates the resulting immutable snapshot.
   - Ranks current candidates using the deterministic gate outcome, the verified preference outcomes, a transparent title/brand relevance heuristic and item price.
   - Shows a recommended candidate only when its latest refreshed snapshot passes the current hard-rule/evidence checks.

   The agent is an orchestration layer over real APIs plus the Groq-compiled Pact workflow. Candidate relevance ranking is a lightweight heuristic; it is not represented as a separate LLM claim. The agent does not create PayPal orders or trigger authorization/capture/void during the search-and-check run. The user chooses the next action.

2. **Control Center (`/control-center`)** — uses AG Grid Community to display recent rows directly from PostgreSQL:
   - Transactions include actual local status and PayPal order/authorization/capture/void identifiers.
   - Policy runs include the recorded deterministic decision, evidence freshness/attribution/security flags, source offer snapshot, Pact snapshot, verification results and policy hash.
   - Rows are sortable, filterable, paginated and selectable. Selection opens record details. The screen is read-only and does not mutate payments.

## Exact snapshot handoff

When a user selects an agent candidate, its exact saved snapshot(s) and corresponding policy evaluation are transferred through browser session storage into Discovery. The Discovery screen focuses the exact selected snapshot instead of silently re-running a new query and replacing the selected merchant offer. Its server-side API still reloads the snapshot by ID when evaluation or checkout is requested.

## Current limitations and honest boundaries

- The purchase Pact is still stored as an approved browser-session object; it is not yet a durable, server-authenticated user approval record. Server endpoints validate the received Pact again at the trust boundary.
- Channel3 search, offer refresh, and Pact evaluations are live, actual service calls. Ranking includes a title/brand heuristic and does not claim perfect semantic product relevance.
- The Control Center currently shows recent policy runs and transactions, not a complete multi-tenant production operations system. It does not include user authentication/authorization or external tamper-resistant audit checkpoints. Deploying publicly requires authentication, authorization, rate limits and operational hardening.
- PayPal is genuinely integrated through its Sandbox APIs and virtual test funds. The offer-bound checkout still uses PactPay's explicitly simulated shipping/tax terms and does not place a retail order with the Channel3 merchant.
- No capture action is issued by the Shopping Agent. Checkout remains a separate explicit user action and the server-side protected gate controls any Sandbox capture/void behavior.

## AG Grid

The implementation uses `ag-grid-react` and `ag-grid-community` Community modules (no Enterprise-only APIs and no Enterprise license key). Official setup documentation: https://www.ag-grid.com/react-data-grid/installation/.

## Run

From the project root, apply the patch, then run `pnpm install` so `pnpm-lock.yaml` records the new AG Grid Community dependencies. Start PostgreSQL with `pnpm db:up` and run `pnpm dev`. From the Composer, approve a Pact and continue to the Shopping Agent. Open Control Center to see persisted transaction and policy records.
