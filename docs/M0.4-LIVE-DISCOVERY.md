# M0.4 — Live catalog discovery and evidence binding

## Goal

Replace the Policy Lab's simulated shopping data with real Channel3 catalog observations without letting browser-submitted fields become financial evidence.

## Trust boundary

1. The server calls Channel3 using `CHANNEL3_API_KEY`.
2. The response is normalized and malformed or non-HTTPS merchant links are dropped.
3. Each exact product-offer listing is saved as an immutable snapshot row with a local observation time and expiry.
4. The browser receives a snapshot UUID and display fields.
5. Evaluation accepts only the snapshot UUID, reloads the stored row, and constructs evidence whose subject reference equals that snapshot ID.
6. A local freshness window of 60 seconds applies from retrieval time. This is an application policy, not a provider source timestamp.

## Known data vs. unknown data

Channel3 Search gives structured catalog products and offers including title, brand, images, merchant URL, price/currency, availability, condition, and category attributes when present. Do not infer RAM from title/description; this patch only accepts a structured RAM attribute.

The current search response does not establish shipping fees, final landed total, delivery date, or return terms. These remain unknown in the purchase pact and block full settlement eligibility. A product price under the budget is only a preliminary screen.

## Non-goals

- No PayPal order or authorization is created from this flow.
- No capture or void calls are added.
- No prompt-injection detection is claimed.
- No product is represented as fully compliant when required evidence is missing.
