# M0.1 Acceptance Checklist

## Environment
- [ ] `apps/web/.env.local` contains `DATABASE_URL` plus the Sandbox app Client ID/Secret.
- [ ] `PAYPAL_BASE_URL` is exactly `https://api-m.sandbox.paypal.com` (no backslash before `://`).
- [ ] PostgreSQL container is healthy.
- [ ] App is running with `pnpm dev`.

## End-to-end payment proof
- [ ] Enter `$2.00` and create an order.
- [ ] Buyer approval is performed with the Sandbox Personal account.
- [ ] Return URL contains both PayPal `token` and PactPay `transactionId`.
- [ ] The success page displays a local transaction ID, PayPal order ID, actual authorization ID, amount/currency, and authorization status.
- [ ] PactPay reports `AUTHORIZED` only when the nested authorization status is `CREATED` and amount/currency match.
- [ ] UI does not dump payer address/email or the full PayPal API response.
- [ ] No PayPal capture request is made by PactPay.

## Persistence and repeat handling
- [ ] Reloading `/api/paypal/transactions/<transactionId>` returns the same persisted state.
- [ ] Repeated callbacks do not produce a second concurrent authorization request.
- [ ] Audit events include transaction creation, order creation, authorization request and authorization result.
- [ ] Buyer cancel records `CANCELLED` where no authorization has been made.

## Webhook safety (after public HTTPS deployment only)
- [ ] Register the URL under the same PayPal Sandbox REST app that owns the client credentials.
- [ ] Store the generated Webhook ID in `PAYPAL_WEBHOOK_ID`.
- [ ] Valid webhook signature is accepted.
- [ ] Invalid/missing signature is rejected and not processed.
- [ ] Duplicate event ID is idempotently acknowledged.
- [ ] No webhook is configured against localhost directly.
